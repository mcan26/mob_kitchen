Slide 4 — Native Android & iOS Network APIs (Theory 5 & Lab 5) 3:45 – 5:00

Signposting "Let us now examine Lab 5: Native Mobile OS Network APIs in detail."

"Standard Dart sockets cannot read physical Wi-Fi link speed, carrier frequency bands, or Bluetooth adapter state, nor can they acquire an Android hardware MulticastLock. Therefore, in MainActivity.kt and AppDelegate.swift, I implemented a native bridge over MethodChannel('com.mobkitchen/native_network')."

"On Android, it queries ConnectivityManager and NetworkCapabilities for active transport and signal strength, WifiManager for link speed in Mbps, 2.4 vs. 5 GHz band classification, and WifiManager.MulticastLock (simmerlink_udp_manet_lock) so the Wi-Fi chipset does not drop incoming UDP broadcast packets, plus BluetoothManager for BLE radio state. In AndroidManifest.xml, we declare Android 12+ NEARBY_WIFI_DEVICES and BLUETOOTH_SCAN with neverForLocation to protect user GPS privacy. On iOS and our Mac Simulator, AppDelegate.swift inspects BSD POSIX getifaddrs on interface en0."

Slide 5 — MANET UDP Discovery (:41234) vs. Full-Duplex WebSocket (:8765) 5:00 – 6:30

Signposting "This brings me to a core engineering question in EI-1057 (Labs 3 and 4): Why do we combine UDP and TCP/WebSockets in the same local network engine?"

"In lan_sync_engine.dart, Phase 1 uses UDP Broadcast on Port 41234 via RawDatagramSocket. TCP cannot broadcast to a subnet because it requires a unicast 3-way handshake; scanning 254 IPs via TCP takes seconds and triggers OS rate limits. Instead, every 4 seconds, each phone sends a single UDP datagram to 255.255.255.255:41234 and the directed /24 broadcast address."

Highlight Loop Prevention "Once discovered, Phase 2 automatically upgrades to a persistent Full-Duplex TCP WebSocket on Port 8765. Crucially, if two phones discover each other simultaneously and open mutual WebSockets, a naive relay creates an infinite broadcast storm. We solved this by stamping every frame with a unique _pkt_id checked against a 256-entry _seenPacketIds ring buffer, alongside _outboundSocketsByEndpoint socket reuse."

Signposting "Turning to the WPAN IoT layer: BLE 5.0 has a default ATT payload limit of 20 bytes, so sending verbose JSON wastes coin-cell battery energy. We implemented official Bluetooth SIG GATT binary framing using Dart ByteData and C++ ESP32 firmware (esp32_smart_kitchen_node.ino)."

"For our Smart Meat Thermometer (Service 0x181A, Characteristic 0x2A6E), temperature is encoded as a 2-byte signed 16-bit little-endian integer at 0.01°C resolution—for example, 56.00°C is 5600, or hex [0xE0, 0x15]. Jury Q&A Defense Bank (Prepared English Technical Answers)
Q1: "Why did you use UDP Broadcast on Port 41234 for discovery instead of scanning all 254 IP addresses with TCP?"
"Scanning a /24 subnet with TCP requires up to 254 individual 3-way handshakes (SYN, SYN-ACK, ACK), which takes several seconds, drains mobile battery, and triggers OS firewall rate limits. By contrast, a single UDP Broadcast datagram to 255.255.255.255:41234 and the directed /24 broadcast address (192.168.x.255:41234) via RawDatagramSocket (broadcastEnabled = true) reaches every peer on the local Wi-Fi AP in under 2 milliseconds. Once a peer parses the simmer_beacon JSON, it opens a single targeted TCP WebSocket connection to ws://<peer-ip>:8765/ws."
Q2: "What happens if two phones discover each other via UDP at the same time and both call connectToPeerWebSocket?"
"That creates two parallel WebSocket channels between Phone A and Phone B. Without protection, when Phone A relays an incoming packet to connected peers, Phone B would relay it back infinitely. In LanSyncAndBleCodecEngine, we prevented this in two ways: (1) every JSON frame is stamped with a unique _pkt_id checked against a bounded 256-entry _seenPacketIds ring buffer before processing or relaying, and (2) outbound client sockets are indexed in _outboundSocketsByEndpoint['ip:port'] so periodic 4-second UDP beacons reuse the existing open WebSocket."
Q3: "How does your Android native MethodChannel handle Android 10+ and Android 12+ privacy and Wi-Fi hardware restrictions?"
"On Android 10 (API 29)+, NetworkCapabilities.signalStrength provides transport-layer RSSI directly from ConnectivityManager, supplemented by WifiManager.connectionInfo for link speed (Mbps) and 2.4/5 GHz frequency (MHz). Because Android Wi-Fi chipsets filter incoming UDP broadcast frames by default to save power, MainActivity.kt acquires a WifiManager.MulticastLock (simmerlink_udp_manet_lock). Finally, in AndroidManifest.xml, we declare NEARBY_WIFI_DEVICES and BLUETOOTH_SCAN with android:usesPermissionFlags='neverForLocation' so we never harvest user GPS location."
Q4: "Why encode BLE GATT telemetry in 2-byte and 3-byte Little-Endian binary instead of sending JSON over BLE?"
"The default BLE ATT MTU is 23 bytes (20 bytes of usable notification payload). A JSON string like {\"temp_c\":56.00,\"weight_g\":125.4} exceeds 32 bytes, requiring fragmentation and higher radio duty cycle on coin-cell probes. By following Bluetooth SIG GATT specifications—0x2A6E (signed int16 little-endian, 0.01°C) and 0x2A9D (1-byte flags + uint16 little-endian, 0.1g)—our payloads are just 2 bytes and 3 bytes, cutting radio airtime by over 90%."
